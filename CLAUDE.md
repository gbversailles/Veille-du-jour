Veille du jour — fiche du projet

Ce fichier résume le projet pour reprendre le travail sans contexte. À lire en entier avant toute modification. Le dépôt est public : ne jamais y écrire de données personnelles (adresse, nom, notes privées).

Le propriétaire
Pharmacien hospitalier, francophone : toujours répondre et commenter en français.
Pas d'ordinateur personnel : il travaille depuis son téléphone ou un poste d'hôpital. Expliquer les manipulations GitHub pas à pas, simplement.
Il ne veut aucun service payant : uniquement des sources gratuites et sans carte bancaire.
Préférences de présentation : sobre, lisible, blocs repliables, peu d'informations affichées d'emblée.

Accès GitHub : si la session Claude a un accès en écriture (push) à ce dépôt (clone + commit + push possibles), modifier et pousser les fichiers directement — y compris template.html, page_du_matin.R, referentiel.html, referentiel.json, posologie.html — plutôt que de donner le code au propriétaire pour qu'il le dépose lui-même via l'interface web GitHub (ce qui oblige à supprimer/réuploader un fichier à la main). Dans ce cas, le workflow peut aussi être déclenché directement (ex. `gh api repos/gbversailles/veille-du-jour/actions/workflows/page-du-matin.yml/dispatches -X POST -f ref=main`) plutôt que de demander au propriétaire de cliquer sur « Run workflow ». Si la session n'a pas cet accès (pas d'outil de push GitHub disponible), revenir à la méthode manuelle habituelle et l'expliquer pas à pas.
Ce que fait le projet

Une page d'accueil personnelle, régénérée automatiquement et publiée sur GitHub Pages (https://gbversailles.github.io/Veille-du-jour/).

page_du_matin.R : script principal. Récupère les données, construit une liste et remplit template.html avec le paquet R whisker (syntaxe Mustache). Écrit public/index.html.
template.html : toute la page (HTML, CSS, JavaScript). Le JavaScript gère : météo selon la position, repli des blocs, réglages, avis, bibliothèque, tâches, outils, apparence. Apparence (localStorage veille-du-jour:apparence) : couleur, thème, ordre des blocs et blocs masqués (ap.masques, cases à cocher dans Réglages, attribut hidden sur la section).
reglages.txt : réglages au format cle = valeur, valeurs multiples séparées par ;. Modifiable depuis la page.
favoris.csv (nom,lien,categorie), avis.csv (pmid,avis,date), bibliotheque.csv (pmid,titre,source,lien,theme,ajoute) : écrits par la page via l'API GitHub.
referentiel.html et referentiel.json : référentiel STP (fiche : tuiles Demi-vie/Tmax, puis « Cible thérapeutique et seuils » rendu par rendreCible() en pile centrée façon fichier Excel du propriétaire : bandeaux gris (.cp-entete) par type de prélèvement, vraies cibles centrées en gros (.cp-val) et placées en premier dans chaque bandeau, aides à la cible en petit gris (.cp-aide : règles × CMI, « Infections documentées », Cmax voie orale, « Pour dose… »), toxicités en gros rouge, phrases sans valeur en note (.cp-note) ; Demi-vie/Tmax en pastilles compactes ; tableaux à colonnes « Résiduelle | Css » (ex. céfépime) remis à plat automatiquement en bandeaux ; seuls les vrais tableaux multi-dimensions (paracétamol, ciclosporine, tacrolimus) restent en table, même style ; tester toute modification sur les 142 fiches) (fiches par molécule : cibles, PK, interprétation). Page statique indépendante, publiée à l'adresse https://gbversailles.github.io/Veille-du-jour/referentiel.html. Elle charge referentiel.json en relatif et enregistre les modifications dans referentiel.json via l'API GitHub, avec le même jeton que la page principale (localStorage veille-du-jour:jeton) ; un brouillon est gardé 15 minutes dans localStorage (referentiel:brouillon). Ces deux fichiers ne passent pas par whisker : ils sont copiés tels quels dans public/ par l'étape « Copier le referentiel » du workflow, juste après « Generer la page ».
posologie.html : appli d'adaptation de posologie, avec un moteur bayésien écrit en JavaScript ; tout est calculé dans le navigateur (aucun envoi de données, aucun serveur). Page statique publiée à l'adresse https://gbversailles.github.io/Veille-du-jour/posologie.html, copiée telle quelle dans public/ par la même étape « Copier le referentiel » du workflow (si le fichier existe).
  Modèles : les fichiers R de posologyr sont collés tels quels dans des blocs <script type="text/plain" class="modele-r" data-fichier="…"> et convertis au chargement par le convertisseur intégré (aucune valeur recopiée à la main). Ajouter un modèle = coller le fichier R dans un nouveau bloc + une ligne dans CATALOGUE ; réglages par molécule (covariable du tableau, voie, unité, zone cible, CMI) dans MOLECULES_PK, avec « fiche » quand l'identifiant du référentiel diffère de la clé de l'appli.
  Liens croisés : posologie.html?mol=<clé> ouvre directement une molécule ; l'appli ouvre la fiche referentiel.html#<fiche> dans un nouvel onglet. La liste POSOLOGIE (identifiant de fiche → [clé de l'appli, libellé]) existe en deux exemplaires, dans referentiel.html (bouton « Adapter la posologie » sur la fiche) et dans template.html (liens sous les résultats du bloc Référentiel STP) : les tenir identiques à MOLECULES_PK quand une molécule est ajoutée à l'appli.
commentaires.html et commentaires.json : banque de phrases de validation du propriétaire (catégories → phrases, touche = copie, recherche sans accents, éléments variables T=…h/[date]/posologies surlignés). Publiés tels quels par l'étape « Copier le referentiel ». Ne jamais y mettre de noms, numéros de fax ou établissements (dépôt public). Ne plus les afficher dans posologie.html (essayé puis retiré à la demande du propriétaire : jugé pas beau). Liens depuis le référentiel et le widget de l'en-tête.
Antidotes : referentiel.html, ANTIDOTES (identifiant de fiche → titre, lignes [libellé, texte], sources [lien, libellé]) et ANTIDOTE_BZD (toutes les fiches de classe Benzodiazépines) ; section repliable « Antidote et conduite à tenir » (details.section, fermée par défaut, comme les autres sections) sous la cible, aussi dans la branche des fiches tableau. Contenu uniquement tiré de sources citées (SRLF-SFMU 2020 Ann Intensive Care 10:157, RCP DigiFab et Voraxaze, CAP Québec) : paracétamol, digoxine, méthotrexate, acide valproïque, isoniazide, benzodiazépines ; épuration extra-rénale pour lithium, salicylés, metformine, phénobarbital.
Fiches du référentiel : champs cree (date de création, 2026-10-16 = import du classeur) et maj (dernière modification, posée à l'enregistrement) ; plus de statut « relue ».
Outils : onglets calculatrice, clairance, conversion, demi-vie, surface corporelle, et « Sites utiles » (HopiTox, centres antipoison, GPR, CRAT, DDI-Predictor, Liverpool VIH/hépatites, Antibioclic). referentiel.html : OUTILS_EXTERNES (identifiant de fiche → liens) affiche des boutons vers des outils externes en haut d'une fiche (paracétamol → nomogramme HopiTox).
Bloc « Référentiel STP » : widget compact dans l'en-tête (template.html, classe .ref-entete, entre le formulaire de recherche et la mini-météo « now »), pas une <section data-section> du flux principal (donc absent du réordonnancement des blocs). Recherche rapide sans accents sur le nom, les spécialités (marques) et la classe, 8 résultats au plus affichés dans un menu déroulant (#ref-resultats, position absolute), chacun vers referentiel.html#<id>, plus deux liens (référentiel complet, adaptation de posologie). referentiel.json est chargé par le navigateur (fetch relatif) au premier focus sur le champ #ref-recherche ; message discret si le chargement échoue.
.github/workflows/page-du-matin.yml : génère et publie la page toutes les 30 minutes (4 h–21 h UTC) et à la demande. Ne pas renommer ce fichier : la page et le référentiel déclenchent ce workflow par son nom après un enregistrement (réglages ou referentiel.json).
Blocs de la page et sources
Bloc	Source	Remarque
Veille scientifique	PubMed (E-utilities)	Bouton « Lu ✓ » : ajoute l'article à bibliotheque.csv et le masque (localStorage veille-du-jour:lus) ; à la génération suivante, tout article déjà dans la bibliothèque (lu ou gardé) est retiré de la veille. Tri par mots-clés selon les spécialités choisies, apprentissage à partir de avis.csv. Calculée une fois par jour puis mise en cache (cache/veille.rds, via actions/cache, clé = date + hash de reglages.txt).
Traduction	Google Traduction (gtx), secours MyMemory	Google renvoie souvent 429 depuis GitHub : on bascule alors définitivement sur MyMemory pour le lancement. Quota MyMemory limité : seuls les 8 premiers résumés sont traduits sans MYMEMORY_EMAIL.
Actualité	Google Actualités (RSS), flux RSS officiels de l'ANSM	Une rubrique repliable par sujet (actu_rubriques), la ville toujours en premier et ouverte : ville, politique, faits_divers, france, monde, economie, sante (actualité médicale générale, pas la veille), biologie (biologie médicale, recherche Google Actualités sur 7 jours), ansm, sciences, tech, culture, sport + thèmes libres. 5 articles par rubrique, sans doublon entre rubriques. ANSM : rss/informations_securite, rss/disponibilite_produits_sante et rss/actualites filtrés produitsSante=medicaments ; ces flux ne contiennent que les publications DU JOUR, d'où un historique de 21 jours gardé dans cache/ansm.rds.
Météo, air, pollens	Open-Meteo	Recalculée côté navigateur selon la position si autorisée ; sinon (ou si la génération n'a pas eu Open-Meteo, timeouts ponctuels), le navigateur la recharge pour latitude/longitude de config_json. preparer() réessaie aussi sur échec réseau (retry_on_failure).
Investissement	Yahoo Finance (cours), baromètre mensuel CAFPI (taux Île-de-France, lu dans la page HTML)	Taux IDF : seule la ligne « Sur 25 ans » est gardée (la page CAFPI n'expose que des durées par région, pas de paliers excellent/bon/correct). Tuiles réduites (CSS ciblé [data-section="invest"]).
Trajet et carburant	api-adresse.data.gouv.fr, OSRM (sans trafic) ou TomTom (avec trafic, meilleure heure de départ), prix des carburants (data.economie.gouv.fr)	Adresse du domicile uniquement dans le secret TRAJET_DOMICILE.
Sport	ESPN (API publique non officielle), Jolpica-F1	Football interrogé jour par jour (les plages de dates ne fonctionnent pas). Football : seulement dernier match + prochain match par équipe suivie (PSG, France), classement Ligue des champions retiré sur demande. F1 : pilotes + calendrier (plus de championnat constructeurs). Bouton ↻ (Actualité, Sport) : relance le workflow via l'API GitHub avec le jeton, puis la page interroge data-genere toutes les 20 s et se recharge.
MMA	Sherdog (fiches combattants, HTML lu par lire_sherdog() dans page_du_matin.R), ESPN mma/ufc et mma/pfl en secours seulement	Liste sherdog_mma (nom affiché, identifiant Sherdog, clé de nom) : Gane 293973, Saint-Denis 317103, Imavov 217405, Doumbé 396393, Baki (Chamsoudinov) 340851, Paul Dena (Paul Denis Navero) 408149 — uniquement les gros noms français, les inconnus ne sont pas voulus. Couvre toutes les organisations (UFC, PFL, ARES, Hexagone). On garde le dernier combat (1 au total) et les 3 prochains. Le journal affiche une ligne « Sherdog <nom> : dernier … | prochain … » par combattant. simplifier_nom() : accents convertis par chartr (iconv dépend de la machine), minuscules avant de retirer les non-lettres.
Secrets GitHub (Settings > Secrets and variables > Actions)

TRAJET_DOMICILE, TOMTOM_KEY (facultatif), MYMEMORY_EMAIL (facultatif), MISTRAL_API_KEY / ANTHROPIC_API_KEY (facultatifs, non utilisés actuellement : pas d'offre gratuite accessible).

Cache du workflow : clé unique par exécution (veille-<run_id>) avec restore-keys « veille- », donc chaque génération reprend le cache de la précédente (veille du jour, historique ANSM). La veille n'est réutilisée que si elle date du jour et que l'empreinte md5 de reglages.txt n'a pas changé. Job plafonné à 25 minutes (timeout-minutes).

Pièges déjà rencontrés
whisker : une liste R nommée est traitée comme un objet et non comme une liste à parcourir → lignes vides. Toujours passer des listes non nommées (unname()).
Aucune balise {{ }} ne doit apparaître dans le JavaScript de template.html (whisker la remplacerait). Vérifier l'équilibre des sections Mustache après chaque modification.
GitHub Pages et les navigateurs gardent l'ancienne page en cache : la page compare data-genere et se recharge si une version plus récente existe.
Les fichiers envoyés via l'interface web sont parfois renommés nom (1).R : vérifier qu'il n'y a pas de doublons.
TomTom a renvoyé 401 Unauthorized : vérifier que la clé autorise la Routing API.
Vérifications avant de proposer une modification
Rscript -e 'invisible(parse("page_du_matin.R"))'
Équilibre des sections {{#…}} / {{/…}} de template.html, et node --check sur chaque script.
Ne jamais activer retry_on_failure pour tous les appels : sur les ~100 traductions en série, les relances après délai dépassé ont bloqué une génération plus de 25 minutes. preparer()/get_json() ont un argument relance_reseau, à réserver aux appels uniques (météo).
Le journal du job « Generer la page » contient des lignes de diagnostic (matchs trouvés, traductions, trajets, taux) : s'en servir pour déboguer.
